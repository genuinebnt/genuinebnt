I build the layer underneath the application — job queues, consensus protocols, storage engines, request tracing. Most of my recent work is deliberately close to database infrastructure: understanding how systems like Postgres, Neon, and CockroachDB are built by building smaller versions of the same problems myself.

### Building

**[NotiQ](https://github.com/genuinebnt/notiq)** — Distributed notification platform: 8 Rust microservices over gRPC, backed by a Postgres-native job queue (`SKIP LOCKED`, `LISTEN/NOTIFY`) instead of a broker.

**[genuine.dev](https://github.com/genuinebnt/genuine-dev)** — Personal site and blog on Axum, Maud, and HTMX, with a hand-rolled markdown CMS and a live request-log dashboard.

**db-labs** — Database internals experiments: an LSM-tree storage engine (WAL, SSTables, bloom filters, compaction) and a Raft-based KV store with chaos testing.

**Gossip Glomers** — Solutions to Fly.io's distributed systems challenges, written up individually — replication, consensus, and fault tolerance in practice.

### Focus

Database internals · distributed consensus & replication · storage engines · system design at scale

Working through CMU 15-445/15-721 and *Designing Data-Intensive Applications* alongside the projects above. I also spend time on application security — bug bounty hunting on Bugcrowd and reverse engineering with IDA Pro and Ghidra.
